# 为本地 OMP 提供轻量 MCP 接口

当前只有维护者的本地 OMP 需要访问反馈板，因此在现有 Go 进程中使用官方 Go MCP SDK 提供 `/mcp` Streamable HTTP 接口，不建设面向第三方客户端的 OAuth 平台。匿名请求可读取公开模组、反馈、分类、动态状态和时间线；写请求使用一个关联现有账号的专用 Bearer Token，继续受现有作者／管理员权限约束。

## 接入与认证

- MCP 与网站使用相同的业务操作执行反馈编辑、状态变更和模组新增／编辑；数据库与附件行为保持一致。
- 服务端配置 `MCP_USERNAME` 和 `MCP_TOKEN_SHA256`（支持 `_FILE`），只保留 Token 的 SHA-256 摘要。客户端安全保存随机 Token，经 HTTPS Authorization Header 传递，不进入工具参数、不复用网站 Cookie。替换摘要并重启即可轮换或撤销；未配置时仅开放匿名读取。
- 账号角色在每个写请求执行时读取。普通成员只编辑自己的反馈，且仅在当前、目标状态均允许作者操作时切换；管理员可编辑任意反馈并新增／编辑模组。Token 本身不赋予额外角色。
- 无效的显式凭据不降级成匿名。保留请求大小限制、未知字段拒绝、输入校验和 Origin 检查，不添加 OAuth、细分 scope、授权管理 UI、公私钥认证或全站并发版本改造。

## 工具范围

匿名工具：`list_mods`、`list_feedback`、`get_feedback`、`list_feedback_timeline`、`get_catalog`。列表支持有界分页，反馈支持模组、分类、动态状态筛选；返回公开数据和网页路径，不暴露账号联系方式、服务器路径或未发布附件。

认证工具：`whoami`、`update_feedback`、`set_feedback_status`、`create_mod`、`update_mod`。反馈使用公开 UUID、模组使用稳定数字 ID；编辑采用显式部分更新，省略字段保持原值，合法空字符串才清空。首批不添加删除、批量操作、上传、账号或服务器配置工具。

## 验证与交付

先实现匿名工具并通过真实 SDK HTTP 客户端验证，再添加认证及写工具。使用隔离数据库验证匿名不可写、成员不能越权、管理员模组管理、部分编辑保留正文／附件、网站流程兼容，以及 Token 轮换。提供 OMP 的 HTTP MCP 配置示例，不修改用户实际凭据配置。本地完成不代表线上部署；部署仍需另行备份和授权。

## 取舍

该专用 Token 是为受控客户端选择的简化认证，不是标准 MCP OAuth 自动登录。`/mcp` 若挂在公开站点，仍是网络可达的公开读入口；只有客户端在本地不等于网络隔离。未来需要第三方客户端或多人独立授权时，再用新 ADR 决定 OAuth 或多 Token 管理，不提前实现。
